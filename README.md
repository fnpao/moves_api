# Movies API

Учебный проект асинхронного REST API для управления каталогом фильмов.

## 🎯 Описание проекта
Данный проект представляет собой асинхронное веб-приложение для ведения каталога фильмов. Проект разработан с использованием архитектурного паттерна **Repository** (Репозиторий), разделяющего бизнес-логику приложения и слой доступа к данным. Реализована строгая валидация входящих параметров, автоматическая генерация миграций базы данных и полное покрытие ключевых сценариев интеграционными тестами.

## 🚀 Основные возможности приложения
* **Полноценный CRUD**: Создание, чтение, полное (`PUT`) и частичное (`PATCH`) обновление, а также удаление записей о фильмах.
* **Продвинутый поиск**: Возможность гибкой фильтрации списков по диапазону лет и минимальному рейтингу, а также поддержка пагинации (`limit`/`offset`).
* **Гибкая сортировка**: Сортировка выдачи по названию, году выпуска или рейтингу как по возрастанию, так и по убыванию.
* **Автоматические миграции**: Полный контроль за схемами таблиц и версионированием базы данных.
* **Интерактивная документация**: Автогенерация OpenAPI-схем и встроенные интерактивные интерфейсы Swagger UI и ReDoc для тестирования эндпоинтов.
* **Автоматизированное тестирование**: Настроенная тестовая среда для проверки работоспособности API.

## 🛠 Технологический стек
* **Язык программирования**: Python 3.12+
* **Backend Framework**: FastAPI
* **ASGI Сервер**: Uvicorn
* **Database ORM**: SQLAlchemy 2.0 (Асинхронный режим)
* **Драйвер БД**: aiosqlite (SQLite)
* **Миграции**: Alembic
* **Валидация данных**: Pydantic v2
* **Тестирование**: pytest + httpx (для асинхронных запросов к тестовому клиенту)

## 🚀 Быстрый старт

Для локального запуска и развертывания проекта выполните следующие шаги:

### 1. Клонирование репозитория
```bash
git clone https://github.com
cd movies_api
```

### 2. Установка зависимостей
Рекомендуется предварительно создать и активировать виртуальное окружение (`venv`):
```bash
# Создание виртуального окружения
python -m venv venv

# Активация для Linux / macOS:
source venv/bin/activate
# Активация для Windows (Command Prompt):
venv\Scripts\activate

# Установка необходимых пакетов
pip install -r requirements.txt
```

### 3. Применение миграций базы данных
Создайте таблицы в локальной базе данных SQLite на основе актуальных миграций Alembic:
```bash
alembic upgrade head
```

### 4. Запуск приложения
Запустите ASGI-сервер Uvicorn с автоматической перезагрузкой при изменении кода:
```bash
uvicorn src.main:app --reload
```
Приложение запустится локально по адресу: **http://127.0.0.1:8000**  
Интерактивная документация (Swagger UI) доступна по адресу: **http://127.0.0**

### 🧪 Запуск тестов
Для проверки корректности работы всех компонентов выполните команду запуска тестов:
```bash
pytest
```

## 🌐 Основные эндпоинты

| Метод | HTTP эндпоинт | Описание операции |
|:---|:---|:---|
| **GET** | `/` | Проверка статуса работоспособности API (Healthcheck). |
| **GET** | `/movies/` | Получение списка всех фильмов с поддержкой фильтрации, сортировки и пагинации. |
| **GET** | `/movies/{id}` | Получение детальной информации о конкретном фильме по его уникальному ID. |
| **POST** | `/movies/` | Добавление (создание) нового фильма в базу данных. |
| **PUT** | `/movies/{id}` | Полное обновление всех полей существующего фильма. |
| **PATCH** | `/movies/{id}` | Частичное обновление отдельных полей фильма. |
| **DELETE** | `/movies/{id}` | Удаление фильма из базы данных по его ID. |

## 🔍 Фильтрация и сортировка

При отправке `GET`-запроса на получение списка фильмов (`/movies/`) доступны следующие query-параметры:

* **Параметры фильтрации**:
  * `year_min` (int) — фильтр по минимальному году выпуска фильма.
  * `year_max` (int) — фильтр по максимальному году выпуска фильма.
  * `min_rating` (float) — фильтр по минимальному рейтингу фильма.
* **Параметры пагинации**:
  * `limit` (int) — максимальное количество возвращаемых записей за один запрос (по умолчанию 10, максимум 100).
  * `offset` (int) — количество пропускаемых записей с начала выборки (смещение).
* **Сортировка**:
  * `order_by` (str) — поле для сортировки результатов. Доступные варианты: `title`, `year`, `rating`. Для сортировки по убыванию перед названием поля ставится знак минус (например, `-rating`, `-year`).

*Пример комплексного query-запроса:*
```text
GET /movies/?year_min=2010&year_max=2023&min_rating=8.0&order_by=-rating&limit=20
```

## 📊 Модель данных

Сущность **Movie (Фильм)** состоит из следующих атрибутов:
* `id` (Integer, Primary Key) — уникальный идентификатор записи в базе данных.
* `title` (String) — название фильма.
* `genre` (String) — жанр фильма.
* `year` (Integer) — год выпуска фильма в прокат.
* `rating` (Float) — средний рейтинг фильма.

## ⚠️ Ограничения базы данных и валидация
На уровне приложения (Pydantic схемы) и на уровне СУБД (SQLAlchemy/Alembic) настроены строгие правила целостности данных:
1. **Ограничения строк**: Поля названия (`title`) и жанра (`genre`) являются обязательными для заполнения (`NOT NULL`), не могут быть пустыми строками и имеют ограничения по длине (название: от 2 до 200 символов, жанр: от 2 до 100 символов).
2. **Валидация года**: Год выпуска (`year`) не может быть меньше **1888** года (официальный год создания первого в истории кинофильма) и не может превышать текущий календарный год.
3. **Валидация рейтинга**: Значение рейтинга (`rating`) строго ограничено диапазоном чисел от **0.0** до **10.0** включительно.
